# TensorQuay Engine: CPU references (test oracles only)

CPU reference implementations that define "correct" for the engine's kernels (TEST-PLAN §2). They
run on the Mac and in CI. They are **never shipped**.

## NVFP4 codec (REF-003, REF-004): accepted
Accepted on 19 Sep 2026; see the [gate record](../docs/evals/2026-09-19-nvfp4-reference.md).
- Code: `src/tq_reference/nvfp4.py`, following the TEST-PLAN §2 codec contract.
- Developer tests: `tests/test_ref003_decode.py`, `tests/test_ref004_quantizer.py`.
- Upstream cross-check: `tests/test_ref004_modelopt_fixture.py`, against
  `tests/fixtures/modelopt_nvfp4_b311c054.json`. That fixture is produced by **running** NVIDIA
  ModelOpt's pinned NVFP4 code (commit `b311c054`, SHA-256-verified files); see
  `tools/modelopt_nvfp4_fixture.py` and the fixture's `provenance` block.
- Independent acceptance tests: `tests/test_nvfp4_acceptance.py`, owned by the technical lead.
- **Global-scale boundary:** any finite float32 scale greater than 0 is accepted, subnormals
  included. A tensor is rejected only if an actual block step (E4M3 scale × g) underflows to
  zero; that is a safety check upstream doesn't have. The fixture includes subnormal-scale
  cases.

## MLA attention core (REF-001): accepted
Accepted on 20 Sep 2026; see the [gate record](../docs/evals/2026-09-20-mla-reference.md).
- Contract: `contracts/mla-attention.md`. Code: `src/tq_reference/mla_attention.py` (float64,
  absorbed NoPE latent attention for one sequence; the scale is always supplied by the caller).
- Independent acceptance tests: `tests/test_mla_acceptance.py` and
  `tests/test_mla_upstream_acceptance.py`, owned by the technical lead; an 80-digit Decimal oracle
  that expands keys and values. Developer checks: `tests/test_ref001_mla_core.py` and
  `tests/test_ref001_upstream_fixture_smoke.py`.
- Upstream cross-check: `tests/fixtures/transformers_mla_770e4c40_core.json` and
  `..._glm_width.json`, produced by **running** pinned Transformers
  `770e4c40d0436082a52dc380f07a9d3f389c99d4` (`glm5_next`); see `tools/transformers_mla_fixture.py`
  and each fixture's `provenance` block. The projection weights, `q_resid` and `latent` are
  **fixture inputs** generated from the recorded seed; `topk_indices` is supplied literally.
  Upstream produces the projected query `inputs.q` and all of `upstream.{key_states, value_states,
  mask, output}`, through `q_b_proj`, `expand_kv`, `build_attention_mask_from_topk` and
  `sdpa_attention_forward`, in float64 on CPU. The three source files defining them are
  SHA-256-pinned and re-verified on every run. A `torch.profiler` trace asserts per case that
  `aten::_scaled_dot_product_attention_math` ran and that no fused kernel did; `--check` compares
  the cases and 21 provenance fields.
- **`--check` targets the recorded environment.** It pins resolved dependency versions along with
  the source and backend evidence, so an exact re-run reproduces that environment. Accepting the
  stored fixtures offline needs only NumPy and stays portable.
- **Fully masked rows are kept, never excluded.** Upstream reaches `aten::_safe_softmax`, which
  returns exact zeros rather than NaN, so those rows match the contract's zero output directly.
- **Scale:** `qk_head_dim**-0.5`. The `glm_width` case pins the GLM-5.3-Flash distinction of a
  256-wide query against a 512-wide latent. Its head count and `v_head_dim` are small only to keep
  that file under 2 MB.
- The independent core and upstream checks pass 193 and eight tests respectively. This accepts
  the float64 attention core only; GPU and full-model gates remain open.

## Routed MoE experts (REF-002): accepted
Accepted on 20 Sep 2026; see the [gate record](../docs/evals/2026-09-20-moe-reference.md).
- Contract: `contracts/moe-experts.md`. Code: `src/tq_reference/moe_experts.py`; float64 routed
  experts with explicit `swiglu_limit`, `[gate; up]` weights and caller-supplied routes/weights.
  Routing weights already include any normalization/scaling; the core applies neither again.
- Independent acceptance: `tests/test_moe_acceptance.py` (166 cases, 100% module lines/branches)
  and `tests/test_moe_upstream_acceptance.py` (22 checks); an 80-digit scalar Decimal oracle.
- Upstream fixture: `tests/fixtures/transformers_moe_770e4c40_experts.json`, generated by running
  the pinned eager expert module. Actual code-object entries prove that the original forward
  and clamped activation ran. Six cases cover top-8, asymmetric dimensions, clamps, zero weights,
  unused banks containing NaN/Inf and precision sensitivity. All rows participate in comparison.
- The authentic router stays in FP32, including its bias; its returned weights are widened
  exactly for both float64 expert arms. This establishes input provenance, not REF-006 acceptance.
- The stable SiLU keeps representable negative-tail values, including at `-720`, where this
  upstream CPU implementation returns zero. The contract documents that numerical difference.
- `--check` verifies the source pins, 24 provenance fields and cases in the recorded environment.
  Its error metric uses a stable norm and includes regression guards for tiny nonzero references.
  Shared experts, production casts, quantization and GPU execution are outside this slice.

## FP32 router (REF-006): accepted
Accepted on 20 Sep 2026; see the [gate record](../docs/evals/2026-09-20-router-reference.md).
- Contract: `contracts/router.md`. Code: `src/tq_reference/router.py`; the single-group GLM path,
  with projection inputs cast before FP32 arithmetic and correction bias used only for selection.
  Output slots and the reference normalization reduction use increasing expert-ID order.
- Independent acceptance: `tests/test_router_acceptance.py` (162 cases, 100% module lines/branches)
  and `tests/test_router_upstream_acceptance.py` (29 checks), with a scalar Decimal oracle.
- Ten actual pinned upstream calls cover 288 experts/top-8, dense projections, cast-sensitive
  inputs, bias-driven selection, epsilon-dominated normalization, zero/subnormal tails and saturation.
  The generator records raw output slots and observes entry into the original upstream forward.
- The earlier `1e-12` FP32 weight rule was corrected before implementation to the contract's
  explicit FP32 budget. Exact selection sets on separated scores and exact curated projections
  remain required. The evaluation records the evidence, measured errors and limitations.
- `--check` compares the entire regenerated fixture, including every provenance field and case.
  Ordinary tests need only NumPy; exact upstream regeneration targets the recorded environment.
  Grouped routing, GPU behavior and end-to-end model quality remain outside this slice.

## Shared test generator (RNG-001…005): accepted
Accepted on 20 Sep 2026; see the [gate record](../docs/evals/2026-09-20-philox-foundation.md).
- Contract: `contracts/philox.md`. Python: `src/tq_reference/philox.py`. Rust: `tq-testkit`.
- Philox4x32-10 uses explicit seed, numeric stream ID and word offset; splitting requests does not change results.
  Uniform float32 values have an exact, shared bit mapping. This is test infrastructure, not token sampling.
- Independent Python acceptance: `tests/test_philox_acceptance.py`, 581 cases with 100% module lines/branches.
  The shared [fixture manifest](../tests/fixtures/philox-v1/manifest.json) pins 199 blocks, 160 stream requests and
  96 uniform conversions. Original Random123 code runs separately as a fresh block/stream oracle.
- Rust/Python execution and checker-corruption tests live in the root `tests/` directory; the ordinary NumPy
  suite does not require a Rust compiler. The contribution guide shows both commands. Earlier fixtures are unchanged.

## Run (offline after the first `uv sync`)
Current result: 1,263 independent acceptance tests and 1,522 total tests, both at 100% package line
and branch coverage. See the [contribution guide](../CONTRIBUTING.md#running-the-current-tests)
for the independent-only command.
```sh
cd reference
uv sync                                           # Python 3.12, pinned by uv.lock
uv run pytest --cov --cov-branch                  # all tests; the gate is 100 % lines and branches
uv run ruff format --check . && uv run ruff check .
```

## Regenerate or check the upstream fixtures (network; downloads pinned torch 2.8.0)
Each generator pins its own dependencies inline (PEP 723) and runs in an isolated environment, so
neither `pyproject.toml` nor `uv.lock` changes and the test environment stays NumPy-only.
```sh
uv run tools/modelopt_nvfp4_fixture.py --check      # re-run upstream; exit 1 on any difference
uv run tools/modelopt_nvfp4_fixture.py              # rewrite the fixture
uv run tools/transformers_mla_fixture.py --check    # also downloads the pinned Transformers archive
uv run tools/transformers_mla_fixture.py            # rewrite both MLA fixtures
uv run tools/transformers_moe_fixture.py --check    # re-run the pinned eager experts and router
uv run tools/transformers_moe_fixture.py            # rewrite the MoE fixture
uv run tools/transformers_router_fixture.py --check # re-run the actual pinned FP32 router
uv run tools/transformers_router_fixture.py         # rewrite the router fixture
```
